# 清晰语言与可用输出

先判断谁要读、要理解或执行什么，以及用户指定的语言和格式。通常可从任务推断，不要把每次写作变成问卷。

读取 [语言标准](references/language.md)。需要选择媒介或交付成果时，读取 [输出标准](references/output.md)。给另一个 Agent 交接时，再读 [交接约定](references/handoff.md)。改写遇到边界时查 [前后对照](references/examples.md)。

采用以下工作方式：

- 先给与任务有关的答案、结果或限制，再补足判断所需的解释。篇幅以任务完整性为准。
- 改写前找出不能改变的事实、条件、例外、数量、否定、不确定性和要求强度。改写后逐项核对，不为流畅补造信息。
- 同一概念保持主称一致。需要执行时写清主体、条件、动作和可观察结果；不清楚主体时不要猜。
- 用具体词和直接动词，保持自然连贯的中文。短句是手段，不是字数考核；无需逐个禁用标点或词语。
- 选择能完成任务且便于阅读、检索和复用的媒介。新增图像、交互或视频，应解决具体理解问题。用户指定媒介时尊重指定。
- 交付前检查内容与来源是否一致、成果是否可用、完成状态是否真实。只说明实际执行的核验；目标尚未完成时，写清可继续推进的下一步。

这些是工作默认值，不覆盖当前用户要求、专业事实、法定原文、引用内容或已有数据接口。普通答复不展示检查清单、规则编号或模式名称；只有请求审校时才解释规则。规范不授权发布、付费或访问新的外部账户。
